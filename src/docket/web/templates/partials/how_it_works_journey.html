{# how_it_works_journey.html — one real item laid onto the path. The container the "How it works" page shows above its explanation, and the whole of what the route answers when a picker link asks through htmx (``HX-Request``): the link's ``hx-target`` is this container and its swap is ``outerHTML``, so the root element here must stay the one ``div#how-it-works-journey`` and everything that changes with the journey must be inside it. Without JavaScript each picker link is an ordinary address, ``?journey=``, and loads the page with that journey. The order inside is fixed: the picker (one link per journey of the city, the one shown marked ``aria-current``), the item's label, note and quoted title, the path with each stop marked from the journey, then a timeline of what the record shows, one card per journey stop. Picking an item is above the path so the marks change below the reader's click. Each picker link has an id, which is what lets htmx put keyboard focus back on it after the swap replaces it. Every date, tally, name and quotation is written in the journey's own file; the database supplies links only, and a stop whose rows are missing or hidden keeps its text and loses its links. A mark on the path always carries its words ("in the record", "not in the record", "not on this item's route"), never colour alone, and it sits beside the stop's link, not inside it. No stop is drawn as the current one: every journey is a finished item, and ``aria-current`` here marks the journey picked, never a stop.
